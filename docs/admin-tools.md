# 现有管理员界面：管理工具与导航配置

> 当前分支增加管理员删除修复、BOP 分类页草稿限制及分类首页迁移，策略 15 需要完整重建 JAR 和镜像。


这次扩展现有 **Wiki 管理 → 内容**，新增“管理工具 / Administration tools”和“导航配置 / Navigation settings”两个原生管理分区。管理员首页 `XWiki.WebHome` 和现有管理员导航也提供入口。沿用 Flamingo/LuxPedia 主题，当前界面固定为 English，不另建管理应用。

只有拥有本 Wiki `admin` 权限的账号能读取管理数据或执行管理操作。角色计数使用当前 Wiki 用户组，用户、用户组和权限配置继续链接到原生管理器；没有建立第二套账号系统，后续可接若依。

## 现有 Mac 实例升级（8081）

当前分支需要 **`luxpedia-workflow-policy-15`**；即使已经安装策略 14，也要重新构建 JAR 和镜像。先按原有流程备份数据库和 XWiki 数据卷，保留原项目目录、`.env`、`.secrets`、Compose 项目名和数据卷。在项目目录依次执行：

```bash
git switch feat/article-translation &&
git -c http.version=HTTP/1.1 pull --ff-only origin feat/article-translation &&
docker run --rm -v "${PWD}:/workspace" -v manu-wiki-maven-cache:/root/.m2 \
  -w /workspace maven:3.9-eclipse-temurin-17 \
  mvn -f extensions/workflow-policy/pom.xml clean package &&
docker compose -f compose.yaml -f compose.workflow-policy.yaml \
  up -d --build --force-recreate --wait xwiki &&
NO_PROXY=127.0.0.1,localhost no_proxy=127.0.0.1,localhost \
  python3 scripts/apply_workflow.py --base-url http://127.0.0.1:8081 --apply
```

保留 `.env` 原有 `XWIKI_PORT=8081`；若使用其他 Compose override，重建时也保留该文件。Maven 首次下载依赖正常，命名缓存卷避免以后重复下载。无需重新初始化数据库。不要执行 `docker compose down -v`。

启动后管理员登录，强制刷新浏览器，再访问：

- 管理工具：`http://127.0.0.1:8081/bin/admin/XWiki/XWikiPreferences?section=LuxPediaOperations`
- 导航配置：`http://127.0.0.1:8081/bin/admin/XWiki/XWikiPreferences?section=LuxPediaNavigation`
- 管理员首页：`http://127.0.0.1:8081/bin/view/XWiki/`

日后普通重启只需 `docker compose -f compose.yaml -f compose.workflow-policy.yaml up -d`；升级代码才需要完整步骤。

## 策略 11 升级时权限迁移报编辑锁错误

若 `PolicySetup` 报 `Editing right expired or belongs to another editor`，同时错误页面是带附件的旧草稿，这是策略 11 的迁移兼容问题。附件深复制导致旧逻辑把权限迁移误判为内容编辑。策略 12 在取得文档守卫后读取最新草稿，仅对内部迁移克隆的同步保存使用受保护的权限更新通道；保留正文、标题、附件、工作流、内容作者、放弃状态及租约的持有人、代号和截止时间。普通保存仍校验编辑权。

按上面的完整命令更新、重建 JAR/镜像、重建容器后重新执行安装器即可；之前已成功创建的配置可重复应用，不需要删除出错草稿或手动接手。

## 管理工具

- BOP 分类首页的旧 Velocity 列表会在安装时迁移到受保护渲染器；安装器不改写 `Drafts` 中带编辑锁的关联副本。策略 15 部署时会隐藏并禁止编辑者打开已有分类首页草稿；管理员可通过 XWiki 原生删除将误创建的副本移入回收站。
- **统一概览**：当前管理员、编辑者、审核者、读者和未分配用户计数；嵌套组沿用现有角色解析。一个人可属于多个角色，角色人数不能相加视作总人数。
- **编辑统计**：最近 7 / 30 / 90 天，Knowledge 和 Drafts 默认语言页的保留主要修订数、产生这些修订的账号数和前 20 位账号。统计包含主要工作流保存；不是在线人数或阅读量，已删除页面和被清理的历史不计入。
- **运行状态**：XWiki/策略/Java 版本、当前 JVM 运行时长和堆内存、持久化目录所在文件系统的空间、数据库查询、工作流服务、回收站、请求写入守卫和附件存储的可用状态。这是应用检查，不能代替完整健康监控；不探测 Docker socket，容器和备份状态明确显示“未接入”。不暴露服务器路径和凭据。
- **批量删除**：Knowledge / Drafts 业务页搜索、分页，每次最多选 20 页；先预览页名、版本、翻译和附件数量，再确认移入原生回收站。分类页会显示为“受保护”但不可选；根首页、配置、系统目录页不提供删除。占用中或审核中的稿件及其发布目标拒绝操作。不递归删除子页面，不提供永久删除。
- **批量恢复**：从原生回收站选条目，预览后确认。翻译按原生回收站分别列出，需先恢复默认语言；同批次会先恢复默认语言。已有同名页面时拒绝覆盖。恢复草稿保留内容、附件及工作流，清除旧编辑租约，之后按现有“接手编辑”流程修改。

预览凭据绑定当前管理员和 Wiki，5 分钟有效且仅能使用一次。执行时重新检查页面版本、翻译和占用；冲突逐项显示，已成功的条目不会回滚。删除/恢复记录写入应用日志。停用回收站时不能批量删除，恢复保存未成功时不会清除回收站原件。现有原生回收站入口仍可用。

## 导航配置

- 图形化增删、修改、排序和调整层级，配置中英名称、站内页面引用或 HTTP(S) 地址、父菜单、侧栏/顶部位置、启用状态和显示角色。最多 50 项、4 层，检查循环和跨 Wiki 引用。
- 配置管理的菜单显示在现有顶部导航与侧栏的附加区域，保留系统原有菜单。此入口管理自定义站点菜单，不接管 Flamingo 全部系统菜单或改变原生主页树。
- 站内目标还须当前访问者有查看权限；隐藏父项时其子项也隐藏。菜单显示角色不授予页面权限。
- 分类级页眉、页脚支持中英文纯文本和“继承至子分类”；最多 100 条，使用最近匹配的可见分类设置。保留全局页眉页脚，不执行 HTML、脚本或 Wiki 宏。
- “保留此项”仅修改当前表单，最后点击“保存配置”才写入服务器；同一配置被另一管理员先保存时提示冲突。
- 页面二维码可统一开关，在可见的业务页面标题旁显示。二维码在浏览器本地生成，可下载 PNG，链接为本页正式地址且去掉查询参数与片段，不含会话令牌；仍受原有登录和页面权限保护。`127.0.0.1` 地址只能在本机访问，手机扫码须使用部署后的内网域名。

二维码使用随仓库打包的 `qrcode-generator` 1.4.4，来源 npm 同名包，保留 MIT 许可证；`jsqr` 仅用于测试独立解码校验，不在运行页面加载。

## 验证与实例验收

Java 测试覆盖管理员、POST/CSRF、版本冲突、一次性预览、占用/审核拒绝、恢复不覆盖与失败保留回收站，以及菜单循环、目标权限和私密配置过滤。浏览器测试覆盖现有管理分区、预览确认/取消、恢复、双语菜单、原有导航保留、未保存输入和二维码独立解码。安装器另有离线注册与 ACL 检查。

自动验证没有访问用户 Mac 上的 XWiki，也没有删除实际资料。升级后建议用可丢弃测试文章验证：普通用户打不开管理接口；管理员预览后取消不改变页面；确认删除进入回收站，恢复后正文及附件完整；新建同名页后恢复被拒绝；占用和待审核稿件不能批删；两位管理员同时改菜单时后保存者遇到版本冲突。
