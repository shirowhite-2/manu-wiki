# 图片、视频和文件插入正文

富文本编辑器上方统一提供 **插入附件**，可筛选全部附件、图片、视频和文件。列表读取当前文章的附件，手动上传和已经导入为本页附件的资料采用同一入口。draw.io 分享链接继续使用旁边的 draw.io 插入入口。

## 使用步骤

1. 新页面先保存一次。使用原生附件面板上传文件，或点击 **上传／管理附件** 在新标签页管理附件。
2. 回到编辑器点击 **刷新附件**，选择文件并点击 **插入正文**。原生编辑器上传完成后也会刷新列表；在其他页面上传、导入后可手动刷新，不需要重载未保存文章。
3. 保存并预览，确认后提交审核。知识库中的修改仍经关联草稿审批生效。

| 类型 | 正文中的内容 | 点击行为 |
| --- | --- | --- |
| PNG、JPEG、GIF、WebP、SVG、BMP、AVIF、APNG、ICO | 原生图片 | 直接显示，可用原生图片工具调整 |
| 视频 | 原生 Embed 块宏 | 查看模式播放，支持的格式取决于浏览器 |
| PDF | 文件名、下载和附件列表链接 | 文件名打开原附件，浏览器及响应设置支持时可查看；也可下载 |
| Word、Excel、PowerPoint、其他文件 | 文件名、下载和附件列表链接 | 文件名打开本篇文章的附件列表；下载链接取回原文件 |

未部署 Office 在线查看／编辑服务，不会把私有附件交给外部 Office 查看器。PDF 使用浏览器自身的查看能力，未安装第三方预览服务。

## 图片与导入

只上传或批量导入附件，不会自动决定图片在正文的位置。编辑者可选中图片插入光标位置；已有图片引用的导入文章继续按原引用显示。Word 内嵌图片提取、外部 Wiki 转换和批量导入映射属于导入流程，不能由附件选择器替代。`scripts/plan_import.py` 仍是只读盘点工具，不上传或转换文件。

当前工具仅列出本篇文章的附件。跨文章复用可使用原生图片／链接选择器，保留源页面的查看权限要求。

## 发布与权限

图片使用原生图片插入接口，视频使用原生 `xwiki-macro-insert` 命令插入独立 Embed 宏。文件链接保留原生 `data-reference`、`data-linktype` 信息，由编辑器转换为相对附件引用；附件列表使用当前文章的空文档引用和 `viewer=attachments` 参数。

保存的引用不固定指向 `/bin/download/Drafts/...`。原生工作流复制附件并发布后，它们可在正式文章上下文中解析。插入工具不复制、上传或移动文件，也不更改 ACL；附件的存在、发布复制和授权仍由 XWiki／工作流处理。撤回、锁定、审核和发布规则沿用原流程。

原生实体序列化处理中文、百分号、`@`、冒号等名称，显示文字使用 DOM 文本节点，文件名不会被当作 HTML。富文本标记协议无法可靠表示的 `|-|` 名称显示失败提示，不擅自删改名称；可改用原生选择器，或由管理员评估重命名及已有引用。

## 更新已有实例

保留已有 `LuxPedia.Code.VideoInsertScript` 扩展身份，以统一工具替换旧的视频工具。附件功能本身只更新界面；当前分支新增的收藏功能需要策略 9，从策略 8 更新时须按[个人收藏部署说明](personal-favorites.md)完整构建组件和镜像。已运行策略 9 的实例后续更新界面时，可直接执行安装器：

```bash
NO_PROXY=127.0.0.1,localhost no_proxy=127.0.0.1,localhost \
python3 scripts/apply_workflow.py --base-url http://127.0.0.1:8081 --apply
```

完成后强制刷新浏览器。离线浏览器回归使用本地 HTTP 和编辑器接口夹具，不能替代真实 CKEditor 转换和工作流发布。实际验收应由 editor 在关联草稿插入中文名图片、视频、PDF、DOCX 和 XLSX，保存预览后送审，由独立 reviewer 发布，再由 reader 检查正文图片、播放、PDF、附件列表及下载。同时检查待审稿无法修改附件、正式版附件存在，以及重新起草后的行为。
