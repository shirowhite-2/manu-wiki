# 页面浏览器、正文组件与 Excel/CSV 导出

> 当前整合分支已升级为策略 **13**，已安装策略 10 / 11 / 12 也须重建组件和镜像，按[最新升级命令](admin-tools.md#现有-mac-实例升级8081)执行。下文仅界面更新的描述是该功能初次引入时的情况。


入口沿用现有 LuxPedia 主题和可视化编辑器；当前界面固定为 English。此功能建立在编辑锁策略 10 之上，不更改 Java 运行组件或角色权限。

## 页面浏览器：筛选文章属性

从 **Knowledge / 知识库 → Document library / 文档库 → Page browser / 页面浏览器** 进入，也可直接打开：

`http://127.0.0.1:8081/bin/view/LuxPedia/Help/PageBrowser`

可组合筛选区域、分类、负责人、工作流状态、标签和更新时间，并搜索清单文字、排序、切换每页条数、跳页。默认显示有效的知识库内容，归档文章可通过状态筛选查看。有草稿查看权限的账号也可选择 Drafts；已发布的工作副本不重复展示，其他人的已放弃草稿仅管理员可列出。负责人来自文章属性，与临时编辑权持有人分别管理。无分类属性的历史页面按原所在空间展示；没有负责人则保留为空。

服务器先检查每个页面的 VIEW 权限，再输出标题、地址及元数据。浏览器只筛选这份已授权的清单，下载不读取未显示给当前账号的其他页面，也不增加访问权限。列表内不执行用户提供的查询文本。

当前筛选、排序和分页在已经渲染的清单上运行，进入浏览器时会加载有权读取的页面元数据。规模取决于页面数量，附件的 GB 数不等于列表行数；若导入后有数万篇文章，应将该清单升级为按权限过滤的服务端分页，避免一次输出过多页面。

## 正文组件：插入后独立编辑

在文章草稿的可视化编辑器上方打开 **Content components / 内容组件**：

| 组件 | 填写内容 | 插入结果 |
| --- | --- | --- |
| 日期 | 日期名称、日历日期 | 普通正文中的固定日期，例如“生效日期：2026-12-15” |
| 任务清单 | 每行一项任务，可选统一负责人和截止日期 | 含 ☐ 的原生项目列表；光标放入任务后可切换为 ☑ |
| 决策概览 | 日期、决策及依据、负责人、状态 | 可通过原生编辑器增减行列的正文表格 |

任务单次可插入 1–100 项。光标放在任务项中，点击 **Toggle task completion / 切换任务完成状态**，状态变化会加入编辑器的修改记录。查看页保持只读。切换菜单语言不改动已输入正文或尚未插入的组件字段。

每次插入都是文章自己的正文副本，保存、预览、提交与审批仍走现有流程，编辑者须持有草稿编辑权。组件默认设置的变化不会自动修改已审核文章。此版本提供这三种常用插入组件及说明页，未引入完整的第三方 Content Droplets 管理套件，也没有新增全站任务中心、任务提醒或跨文章决策汇总。

说明页：`/bin/view/LuxPedia/Help/ContentComponents`，也可从编辑器的组件说明按钮或帮助中心进入。

## 表格筛选与导出

页面浏览器和普通正文表格提供搜索、排序、分页、**Export Excel / 导出 Excel** 和 **Export CSV / 导出 CSV**。每张正文表格独立筛选；导出包含该表当前筛选结果的所有分页，并按所选顺序排列。

- Excel 为真正的 `.xlsx` / OOXML 工作簿，中文、换行和前导零以文本保留。公式样式的输入仍作为文本，不创建公式或外部链接。
- CSV 使用 UTF-8 BOM、双引号和 CRLF，处理逗号、引号与换行，并将可能被电子表格解释为公式的文本保持为文本。
- 导出表格值，图片、附件和字体/颜色等排版不嵌入文件；不提供 Excel 附件在线编辑或将附件自动转换成正文表格。
- 含合并单元格的表格保持原有展示，完整导出；Excel 保留合并区域，CSV 使用空单元格占位。这类表格的筛选、排序和分页停用，避免破坏原有行列关系。
- 原始汇总行在完整表格中保留；筛选减少数据行时隐藏该汇总，导出也不附带旧汇总。导出不重新计算公式或合计。
- 嵌套表格、含输入控件的交互表格及原生 LiveData/系统列表不自动改造。服务器的页面浏览器使用专门标记启用同一套工具。
- 浏览器单次导出上限为 25 万单元格、1600 万文本字符；Excel 单元格超过 32767 字符会提示改用 CSV，避免截断数据。大型表格应先缩小筛选范围或拆分。

筛选及下载都不会写回 Wiki。读者可导出有权查看的内容；插入和修改正文仍受现有编辑权限、24 小时编辑锁和审核流程限制。

## 部署到已有实例

已运行 `luxpedia-workflow-policy-10` 的实例只需更新分支、运行完整安装器并刷新浏览器：

```bash
git switch feat/article-translation &&
git -c http.version=HTTP/1.1 pull --ff-only origin feat/article-translation &&
NO_PROXY=127.0.0.1,localhost no_proxy=127.0.0.1,localhost \
  python3 scripts/apply_workflow.py --base-url http://127.0.0.1:8081 --apply
```

尚未升级策略 10 的实例，应先按[编辑锁升级步骤](edit-locks.md)重新构建组件与 Docker 镜像。本次安装只增加受保护的渲染器、脚本和帮助页，不重写已有文章正文。

代码验证包括权限过滤后的实际 Velocity 输出、普通/合并表格、跨页筛选导出、真实 OOXML ZIP/XML 与独立 Excel 读取库检查，以及组件插入、任务状态修改、只读、取消、English-only 控件和窄屏布局。浏览器使用模拟原生编辑器接口；部署后仍需检查实际 CKEditor 的 WikiText 往返转换、保存及审核发布。
