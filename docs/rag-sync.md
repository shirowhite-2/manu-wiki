# LightRAG 手动同步

策略 16 在 **Wiki 管理 → 内容** 新增“LightRAG 同步 / LightRAG sync”原生管理分区，地址为 `/bin/admin/XWiki/XWikiPreferences?section=LuxPediaRag`。它把已发布 Knowledge 文章的纯文本发送到与 imai 知识库共用的 LightRAG 服务（`imai/lightrag_server`，1.5.0），供以后接入的对话模型检索。Wiki 仍是最新、完整的知识库；LightRAG 只保存检索用的文本副本。

## 同步什么

- **范围**：只处理 `Knowledge` 及其子空间中带发布工作流对象、`istarget=1` 且状态为 `published` 的默认语言页面。`Drafts`、草稿、隐藏页、分类首页、翻译和系统页不发送。
- **分类**：文章归入所在位置最近的已启用分类。默认启用除 Archive 外的一级分类；管理员可在分类表中逐项开启或关闭，子分类未启用时并入最近的已启用上级。不在任何分类下或分类全部未启用的文章不发送，预览中显示数量。
- **内容**：发送标题、页面引用和正式地址、分类路径、标签、摘要、负责人、适用版本，以及正文纯文本。正文从 XWiki 渲染树提取：保留标题、段落、列表、表格和代码块，去掉图片、视频、draw.io、HTML/原始块、附件链接、`data:` 地址和长 base64 串。**附件和图片不发送。** 单篇超过“每篇文章最大字符数”（默认 200000）时跳过并在预览中显示。
- **触发**：保存、发布页面不会调用 LightRAG。管理员点击“预览同步”查看待处理变化，再点“开始同步”。预览凭据绑定当前管理员，5 分钟有效、只能使用一次。

## 在 LightRAG 中的存放方式

LightRAG 没有文件夹；**工作区（workspace）是唯一的一层**，且 `file_source` 只保留文件名。因此：

- 每个启用的分类对应一个工作区，名称为 `<前缀>_<分类路径>`，如 `wiki_Technical`、`wiki_Technical_Hydraulics`。只保留 ASCII 字母、数字和下划线；名称重复时追加分类引用的短哈希。
- 分类嵌套不会在 LightRAG 中成为嵌套目录。层级保留在文件名中，如 `Technical__Hydraulics__Pumps-1a2b3c4d5e.md`（结尾为页面引用的短哈希，避免重名），并写在正文开头的 `Category path:` 一行。

## 与其他平台隔离

LightRAG 中还有其他平台（如 imai）的文件。Wiki 遵守以下规则：

- **只写本 Wiki 创建的工作区。** 创建工作区后立即记录到 `LuxPedia.Code.RagSyncState`。如果计划使用的名称在 LightRAG 中已存在但不是本 Wiki 创建的，相关文章失败并显示 `workspace_conflict`，不写入、不删除。“测试连接”会提前列出这类冲突，可改前缀或分类选择。
- **不列出 LightRAG 文档。** 差异只与本地台账比较：每个工作区一页 `LuxPedia.Code.RagLedger_<工作区>`，记录页面、文件名、文档 ID、版本、内容哈希和同步时间。只读取 LightRAG 的工作区名称列表、健康状态和流水线状态。
- **按记录的 ID 删除。** 文档 ID 由 LightRAG 规则 `doc-` + md5(文件名) 预先算出并存入台账；删除只使用台账中的 ID 和工作区。客户端在发出请求前还会再次拒绝非本 Wiki 工作区。
- **服务器上被删除的工作区。** 台账不会自己知道 LightRAG 侧的删除，所以每次“预览同步”都会读取 LightRAG 的工作区名称列表（仅名称）。本 Wiki 的工作区不在列表中时，标记为“已在 LightRAG 中删除”，旧台账不再参与比较，该工作区的全部文章在预览中显示为新增；管理员确认后，同步重新创建该工作区并重新发送。若是有意删除，请取消并停用对应分类。同步过程中遇到 LightRAG 返回 “Workspace has been deleted” 时，该条目失败并做同样标记，下次预览重新发送。因此即使待同步列表为空，“预览同步”也可以点击。
- **被删除后又被他人重建的工作区。** 已标记删除的工作区如果在 Wiki 重建之前又出现在列表中，说明是别人重建的，可能含其他平台文件；Wiki 不写入，显示冲突，由管理员修改前缀或在 LightRAG 中处理后重新预览。若删除和重建都发生在两次预览之间，Wiki 仅凭名称无法察觉，这一情况未处理。单篇文档在 LightRAG 中被手动删除同样不会被发现，除非该文章之后被修改（更新失败会自动改为新增）。
- 设置、状态和台账页面隐藏，仅 `XWiki.LuxManagers` 和 `XWiki.XWikiAdminGroup` 可查看；API 密钥不会回显到页面或接口。

## 差异与执行

每次预览把当前符合条件的文章与台账比较：

| 类型 | 条件 | LightRAG 操作 |
| --- | --- | --- |
| 新增 | 台账中没有 | `POST /documents/text` |
| 修改 | 文本哈希变化 | `POST /documents/update_document` |
| 移动 | 分类工作区或文件名变化 | 旧工作区删除后在新工作区新增 |
| 删除 | 台账有、文章已删除/撤回/移出分类 | `DELETE /documents/delete_document` |
| 仅版本 | 页面版本变化但文本相同 | 不上传，只更新台账 |

删除先执行，然后写入；LightRAG 删除进行中返回 busy 时会等待重试。浏览器分批推进（每批约 20 秒），同步期间请保持页面打开；关闭页面后已完成的项目已记入台账，剩余项目下次预览仍会出现。LightRAG 中途不可达时同步停止，其余变化保留。同一 Wiki 同时只允许一个同步。

LightRAG 接收后在后台切块和抽取实体，Wiki 显示“完成”只表示文本已被接受；检索可用时间取决于 LightRAG 流水线。

## 配置

1. 地址必须能从 **XWiki 服务器（容器内）** 访问，例如 `http://10.41.28.59:19621`。Docker 中的 `127.0.0.1` 指 XWiki 容器本身；LightRAG 在同一台 Mac 上时可用 `http://host.docker.internal:<端口>`。只接受 http(s)，不含账号、查询参数或片段。
2. 当前 imai 的 LightRAG 未启用认证；如以后启用，在“API 密钥”填写，以 `X-API-Key` 头发送。留空保存会保留已存密钥。
3. 选择分类并保存，点“测试连接”，再预览和开始同步。修改分类选择后，受影响的文章在下次同步中显示为“移动”。

## 升级（策略 16）

按[管理员工具](admin-tools.md#现有-mac-实例升级8081)中的完整命令重建 JAR、镜像和容器，再运行 `scripts/apply_workflow.py --apply`。保留 `.env`、`.secrets` 和数据卷，不要执行 `docker compose down -v`。首次升级不会自动同步。

## 验证

Java 测试使用模拟 LightRAG 服务，覆盖：只发送分类内已发布文章的纯文本；修改、仅版本、删除重试及启用子分类后的移动；已有的外部工作区不被写入；工作区在服务器上被删除后于预览或同步中发现并重新发送，被他人重建的则不写入；客户端拒绝非本 Wiki 工作区；预览凭据绑定管理员且一次有效；管理员、POST 与 CSRF 校验；设置校验与密钥不回显。浏览器测试覆盖分类表、设置保存、冲突提示、预览确认/取消和分批进度。

自动测试未连接真实的 imai LightRAG。部署后建议用一个可丢弃的测试前缀（如 `wikitest`）同步少量文章，在 LightRAG 中确认工作区和文件名，然后修改、撤回一篇文章再次同步，确认只影响对应文档。
