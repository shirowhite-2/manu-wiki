# 草稿独占编辑与 24 小时释放

编辑锁最初由策略 10 引入；当前整合分支要求 **`luxpedia-workflow-policy-12`**（[管理员工具](admin-tools.md)），适用于本仓库的 **单个 XWiki 应用容器**。数据库和附件保持原有存储；锁到期不创建第二份文章，也不删除草稿、修订或附件。

## 使用流程

- 在 Knowledge 点击“编辑内容”或原生“编辑”，服务器查找并复用唯一关联草稿；没有时通过原生工作流创建。取得编辑权后打开编辑器。
- 编辑权最长保留 **24 小时**，从取得时开始计算。保存、预览、轮询、重复点击编辑或重启服务都不会延长截止时间。
- 其他有草稿查看权限的账号可以读取已保存内容，看到当前持有人与截止时间；在该编辑权释放前不能修改正文、元数据、附件或提交审核。单纯打开页面不会占锁。
- “保存并预览”保留编辑权；“保存并释放编辑权”先保存并完成预览元数据，再释放，已保存内容留在原草稿。预览页也提供单独的“释放编辑权”。
- 到期后，任何符合权限的编辑者均可点击“接手编辑”，继续同一份已保存草稿。取得编辑权时重新计算一段最长 24 小时的期限。
- 旧编辑器失去编辑权后保留页面里的输入并禁用保存，提示先复制未保存正文。服务端拒绝旧会话继续写入，即使原账号之后重新取得编辑权也不会自动更新旧页面的会话标识。未发送到服务器的文本不会自动变成服务器修订。
- 提交审核会释放编辑租约，并由审核状态继续锁住正文。审批、发布、退回、撤回与放弃/恢复仍走现有流程；退回、撤回或恢复后须明确接手，不能靠等待 24 小时编辑审核中的文章。
- 放弃草稿保留现有软放弃机制并清除编辑权；批量放弃只处理当前持有人仍持有有效编辑权的草稿。管理员要处理其他人的占用，可先“强制释放编辑权”，再接手操作。管理员直接删除的恢复工具保留。

新文章在首次持久化为 Drafts 页面时取得编辑权。Drafts 首页说明正文及系统配置不属于文章编辑锁范围。新增提示使用已有主题按钮和提示框，支持 English / 中文。

## 服务器保证与边界

`LuxPedia.Code.EditLeaseClass` 在默认语言草稿中保存持有人、取得时间、截止时间与随机会话代号，普通对象编辑不能修改这些字段。草稿 ACL 只给当前持有人 EDIT；每次普通写入和提交还会核验账号、期限及会话代号。到期但尚未接手时，即使旧 ACL 缓存仍显示编辑权限，保存校验也会拒绝。

取得、释放与强制释放要求 POST 和 CSRF。关联草稿的查找/创建操作按发布目标串行执行；文档守卫保持到同步请求完成，避免检查通过后被接手请求穿插。出现历史重复关联草稿时停止操作，请管理员核查，不任意选取或覆盖。

官方 XWiki 的空 `absolute-ordering` 关闭了扩展包自动扫描，因此本仓库 Dockerfile 会显式将守卫配置到 Tomcat 10 的 `web.xml` 最外层，保留原有过滤器和扫描设置；启用扫描的其他部署也可由 `ServletContainerInitializer` 注册同一守卫且不会重复。非 Docker 部署需运行 `sh extensions/workflow-policy/configure-filter.sh /实际路径/WEB-INF/web.xml` 并重启。安装器也核验这个请求边界，未启用时停止部署。编辑权随数据库持久化；进程守卫只服务单实例，**多 XWiki 节点部署前须替换为分布式守卫**。后台直接写草稿的集成也须接入受保护的请求流程；不能绕过守卫运行。

## 现有 Mac 实例升级（端口 8081）

先按已有备份流程保存数据库和 XWiki 数据卷，保留当前 Compose 项目名及命名卷。然后在项目目录执行；Maven 首次下载依赖属正常现象：

```bash
git switch feat/article-translation &&
git -c http.version=HTTP/1.1 pull --ff-only origin feat/article-translation &&
docker run --rm -v "${PWD}:/workspace" -v manu-wiki-maven-cache:/root/.m2 \
  -w /workspace maven:3.9-eclipse-temurin-17 \
  mvn -f extensions/workflow-policy/pom.xml clean package &&
docker compose -f compose.yaml -f compose.workflow-policy.yaml \
  up -d --build --force-recreate --wait xwiki &&
NO_PROXY=127.0.0.1,localhost no_proxy=127.0.0.1,localhost \
  python3 scripts/apply_workflow.py --base-url http://127.0.0.1:8081 --apply
```

只运行 Python 不会替换运行中的 Java 组件。升级保留旧草稿与附件；没有有效租约的旧草稿需要先接手。再次应用安装器不会续期、抢占或自动恢复已放弃的草稿。若自己另有 Compose override，也应在重建命令中保留它。

## 验收

代码验证包括固定时钟的 24 小时边界、重复取得不续期、到期接手、旧会话拒写、保存失败不谎报成功、管理员强制释放、同时打开只创建一份关联草稿、请求异常释放守卫，以及浏览器保存/释放、附件 AJAX 校验和保留未保存文本。浏览器使用本地模拟路由，未连接 Mac 上的真实 XWiki。

部署后用两个独立编辑者和一个管理员账号检查：第一人编辑，第二人只读；第一人保存并释放，第二人接手同一地址且能看到保存的正文及附件；旧窗口保存失败；提交审核后任何编辑者均不能改正文；撤回后需接手；管理员强制释放可恢复工作。用一篇可丢弃的测试文章检查实际 CKEditor、原生附件对话框和自动保存；原生控件和插件的写入同样必须携带当前编辑会话代号。
